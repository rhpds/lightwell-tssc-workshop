= 3.2 Bind base and deps in source
:source-highlighter: rouge
:toc:
:toclevels: 2

You now own `lw-student/spring-boot-lw-poc` on Gitea. In this module, carry the evidence from Tracks 1 and 2 into that application's `Dockerfile` and `pom.xml`, then push the two changes. Continue in the Showroom terminal.

Before starting, complete the verified mirror in xref:module-01-hummingbird-verify.adoc[Track 1] and the dependency comparison in xref:module-04-remediated-pin.adoc[module 2.2]. You need the published destination pull spec and the selected version in `~/lightwell-dependencies/pom.xml`.

== Why this control exists

A digest identifies the base image you verified. An exact Maven version identifies the dependency you selected from the workshop advisory. Recording both in application source lets a reviewer see which inputs you intend the build to consume.

image::hummingbird-published-vs-dest.png[Published Hummingbird image mirrored to the destination used by the runtime FROM,width=700,link=self,window=blank]

Use the destination pull spec from Track 1, including its registry host, `hi/openjdk` path, and index digest. `hummingbird-mirror` is the Nexus repository name, not a segment of the image path. The build stage stays on UBI here; you change the runtime stage.

The seed also contains a stale `lightwell-pins.properties` file for the Renovate exercise. That file is a separate record: updating it does not rewrite the Dockerfile or the POM. Leave it unchanged until module 3.3.

== Learning objectives

By the end of this module, you will be able to:

* Retrieve the verified destination pull spec from Track 1's report.
* Replace the runtime base image with that digest-pinned destination.
* Apply Track 2's exact version to the application's default Maven property.
* Compare the two-file diff and verify that the commit reached Gitea.

== Exercise

=== Bind the verified runtime image

Open `/tmp/spring-boot-lw-poc/Dockerfile` in your terminal editor. Use the exact value printed as `DEST_PULLSPEC`; do not reconstruct it from a sample host or a tag.

Change the runtime stage `FROM`. Leave the `AS build` line on UBI. The runtime line is the dest host, the path `hi/openjdk`, and the digest from `DEST_PULLSPEC`. A line that contains `hummingbird-mirror`, `registry.access.redhat.com`, or `:latest` fails the Check.

=== Bind the selected dependency version

Open `/tmp/spring-boot-lw-poc/pom.xml`. Find the first, top-level `<properties>` block, outside any `<profile>`.

Change the default `<commons.lang3.version>` in `pom.xml` to `3.14.0.rhlw-00001`. Use the version you verified in `~/lightwell-dependencies/pom.xml`; keep the application POM and edit only its default property. You already resolved that version from Nexus in xref:module-04-remediated-pin.adoc[2.2]. This commit is the scored git copy. A profile that is never activated leaves the default on `3.14.0`, and that default fails the Check.

Leave `lightwell-pins.properties` as the seed wrote it.

=== Inspect and publish your changes

Before staging, compare your edits. Expect one changed runtime `FROM` and one changed default Maven property. The `AS build` line and `lightwell-pins.properties` should be unchanged.

[source,bash,role=execute]
----
cd /tmp/spring-boot-lw-poc
git --no-pager diff -- Dockerfile pom.xml lightwell-pins.properties
----

Set the author identity and push credentials on this clone so the Showroom shell can push without an interactive password prompt. The credentials are stored in the clone's local Git configuration, outside the committed tree. Do not copy the authenticated remote URL into notes or screenshots.

.Commit the runtime FROM and the default version
[source,bash,role=execute]
----
cd /tmp/spring-boot-lw-poc
git add Dockerfile pom.xml
git status --short
git --no-pager diff --cached
git commit -m "Bind dest Hummingbird runtime and Lightwell default version"
git push origin HEAD
----

== Review

Fetch the remote and compare commit IDs. `HEAD` and `origin/main` should be identical after your push. Inspect `origin/main` so the evidence comes from the remote branch rather than uncommitted local files. The runtime `FROM` must match `DEST_PULLSPEC`, the default property must be `3.14.0.rhlw-00001`, and the properties file should retain its seed values.

[source,bash,role=execute]
----
cd /tmp/spring-boot-lw-poc
git fetch origin
git rev-parse HEAD origin/main
git show origin/main:Dockerfile | grep -E '^FROM '
git show origin/main:pom.xml | awk '/<properties>/ { found = 1 } found { print } found && /<\/properties>/ { exit }'
git show origin/main:lightwell-pins.properties
----

Explain where the destination digest and the selected version came from. If the commit IDs differ, resolve the failed push before continuing. If only a profile contains the new version, correct the default property and push again.

A runtime `FROM` that is still `ubi9/openjdk-21-runtime`, or that names `hummingbird-mirror` or a sample host, fails the Check. The Validate Job grades those committed files.
