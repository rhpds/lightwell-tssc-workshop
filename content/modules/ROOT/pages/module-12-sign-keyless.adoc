Track 4 produced an application image and an SBOM. In this module, confirm that the pipeline signed that application image with Red Hat Trusted Artifact Signer (RHTAS), then verify the signature against the pipeline service-account identity. Continue in the Showroom terminal and your `/tmp/spring-boot-lw-poc` clone.

Track 5 has three outputs: keyless verification evidence in 5.1, a learner-owned signature policy in 5.2, and a second signature plus a public key for Track 6 admission in 5.3. Keep Track 4’s run name, image reference, and SBOM available so you can recognize when a new build replaces them.

== Why this control exists

A signature connects the exact application image you built to the identity that signed it. Here, that identity is the `pipeline` service account in your build namespace. During signing, `cosign` creates a temporary key pair and presents the service account’s OpenID Connect (OIDC) token to Fulcio, the certificate authority. Fulcio checks the token and issues a short-lived certificate that binds the public key to that service-account identity. `cosign` then signs the image digest with the temporary private key, and Rekor, the transparency log, records the signing evidence.

When you run `cosign verify`, it checks the signature against the image digest, validates the certificate and transparency-log evidence, and requires the signer identity and token issuer you specify. In this lab, the expected signer is your build namespace’s `pipeline` service account, and the expected issuer is `https://kubernetes.default.svc`. The Update Framework (TUF) supplies the trusted certificates and public keys used to validate Fulcio and Rekor. Successful verification establishes that the image matches the signed digest and that the signature belongs to the expected pipeline identity.

== The signer URLs

The commands should locate `cosign` on `PATH` and print the signing model and both URL families: internal Services for the pipeline, and Route hints for verification from Showroom. Confirm the hints against the live Routes. A PipelineRun that still contains `apps.<domain>` fails the sign task.

.Read the RHTAS URLs

=== Verify and save the application digest

Resolve the application tag `spring-boot-lw-poc:latest` in the build namespace to its immutable `@sha256:` reference before verification. Avoid concurrent builds while collecting evidence. The identity is the pipeline service account in that namespace. The issuer is the Kubernetes API. Showroom uses the Route hints for TUF and Rekor, because this shell is outside the build NetworkPolicy. `HOME` is `/tmp/lab-home` so `cosign login` does not write a Docker config into the real home directory.

If verify fails, read the SAN from the Rekor entry or from the `cosign verify` error. The identity regexp below is the one this cluster's pipeline service account presents.

The command should return exit code 0 and print a verification block for your application digest.

.Verify the application digest
[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap lab-gitea -o jsonpath='{.data.student_build_namespace}')"
TUF="$(oc -n trusted-artifact-signer get configmap lab-rhtas -o jsonpath='{.data.tuf_url_hint}')"
REKOR="$(oc -n trusted-artifact-signer get configmap lab-rhtas -o jsonpath='{.data.rekor_url_hint}')"
IMAGE="$(oc -n "$BUILD_NS" get istag spring-boot-lw-poc:latest -o jsonpath='{.image.dockerImageReference}')"
[[ "$IMAGE" == *@sha256:* ]] || { echo "No immutable application reference"; exit 1; }
mkdir -p /tmp/lab-home
export HOME=/tmp/lab-home
cosign initialize --mirror="${TUF}" --root="${TUF}/root.json"
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000
cosign verify \
  --rekor-url="${REKOR}" \
  --certificate-identity-regexp="^https://kubernetes.io/namespaces/${BUILD_NS}/serviceaccounts/pipeline$" \
  --certificate-oidc-issuer="https://kubernetes.default.svc" \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE}" > /tmp/track5-keyless-verification.json
VERIFY_STATUS=$?
cat /tmp/track5-keyless-verification.json
test "$VERIFY_STATUS" -eq 0 || { echo "Signature verification failed"; exit 1; }
----

Save the reference only after verification succeeds. Track 6 promotes the final verified digest.
