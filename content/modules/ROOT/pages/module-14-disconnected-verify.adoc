= 5.3 Add and verify the admission signing key
:source-highlighter: rouge
:toc:
:toclevels: 2

In this module you prove that the application digest also carries a signature you can verify with a public key, without calling Fulcio.

This final module in Track 5 prepares the application image for public-key admission in Track 6. Module xref:module-12-sign-keyless.adoc[5.1] established its keyless signature through Trusted Artifact Signer. The upcoming exercise adds a second signature to the same digest using a cosign key pair held in Showroom: the private key signs the image, and the public key verifies that signature and becomes the trust material for admission. The existing keyless signature remains available.

This demonstrates a verification approach that can be used in a disconnected environment when the image, signature, and trusted public key are available there. The workshop cluster remains connected and retrieves the signature from its registry, so the exercise does not demonstrate physical network isolation or offline artifact transfer. Mirrored TUF for keyless verification and a simulated media transfer are covered separately in xref:appendix-disconnected-playbook.adoc[Appendix: disconnected transfer].

== Why this control exists

Keyless signing needs Fulcio when the signature is created, and a TUF root when it is verified. A keyless verifier uses certificate and trust-root evidence; it does not ask Fulcio to issue a new certificate at verification time. This lab adds a public-key verification path for Track 6 admission. You add that second signature here, on the same digest. The keyless signature stays on the image.

Native `ImagePolicy` `signedEmail` cannot hold the 5.1 Kubernetes service-account URI. xref:module-15-gitops-admission.adoc[6.1 GitOps + admission] therefore renders CRI-O policy as `policyType: PublicKey` from the PEM you publish. That PEM is ConfigMap `lab-cosign-pubkey` in namespace `tssc-admission`. xref:module-12-sign-keyless.adoc[5.1 Sign] draws the keyless column. This module is the other signature: `~/lab-trust/cosign.key` signs, and `cosign.pub` is what admission will trust.

Lightwell Network and Lightwell Clearinghouse Premier artifacts may already have their own signatures. This Check is the application image. Premier does not replace the key pair.

[NOTE]
====
The private key stays on this terminal. It does not go in Git, and it does not go in a screenshot. `cosign.key` is the file to keep out of the commit.
====

In a customer engagement, a disconnected plant verifies with keys, and it keeps a mirrored TUF root for any artifact that was signed keylessly. You generate the pair on this terminal and sign the digest you already built. Red Hat does not operate a data diode on this cluster. An empty `COSIGN_PASSWORD` is for this non-interactive lab terminal. A customer plant uses a real passphrase.

== Learning objectives

By the end of this module, you will be able to:

* Generate a cosign key pair under `/home/lab-user/lab-trust` and sign the application digest with `--key` and `--tlog-upload=false`
* Verify that digest with `cosign verify --key`
* Publish `cosign.pub` to ConfigMap `lab-cosign-pubkey` so 6.1 can render ImagePolicy
* Explain that a Lightwell library signature is a different layer from this application key

== The digest you already signed

`cosign` is already on the Showroom `PATH`. Success is a `dockerImageReference` for `spring-boot-lw-poc:latest` in the build namespace, and the saved verified reference from 5.1. An existing key pair is expected on a return visit; reuse it.

BUILD_NS="$(oc -n gitea get configmap lab-gitea -o jsonpath='{.data.student_build_namespace}')"

ls /home/lab-user/lab-trust 2>/dev/null || echo 'lab-trust empty (expected before the Exercise)'
----

== Exercise

=== Generate or reuse your signing key

Generate the key pair in `~/lab-trust` if `cosign.key` is not already there. `export HOME=/tmp/lab-home` exists so `cosign login` does not write a Docker config into the real home directory. The `--key` path and the ConfigMap `--from-file` path stay on `/home/lab-user/lab-trust`, because a tilde would follow the temporary `HOME`. `--tlog-upload=false` keeps this signature off the public Rekor log. That is the disconnected procedure: the signature travels with the digest, and verify uses `--insecure-ignore-tlog` on the next step.

ImagePolicy `signedEmail` cannot store a service-account URI. The public key is what 6.1 will render. Success is `cosign.pub` on disk, `cosign sign` exiting 0, and ConfigMap `lab-cosign-pubkey` in namespace `tssc-admission` holding that PEM. Put `HOME` back to `/home/lab-user` before the Check.

.Prepare the key pair
[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap lab-gitea -o jsonpath='{.data.student_build_namespace}')"
IMAGE="$(cat /home/lab-user/lightwell-signing-evidence/image.txt)"
CURRENT_IMAGE="$(oc -n "$BUILD_NS" get istag spring-boot-lw-poc:latest -o jsonpath='{.image.dockerImageReference}')"
[[ "$IMAGE" == *@sha256:* && "$IMAGE" == "$CURRENT_IMAGE" ]] || { echo "Refresh 5.1 verification for the current application digest"; exit 1; }
mkdir -p /home/lab-user/lab-trust
cd /home/lab-user/lab-trust
if [[ ! -f cosign.key ]]; then
  COSIGN_PASSWORD="" cosign generate-key-pair
fi
test -s cosign.key && test -s cosign.pub || { echo "Incomplete key pair; recover it before continuing"; exit 1; }
----

=== Sign the verified digest and publish the public key

Use the same immutable `IMAGE` selected above. The signing command must succeed before you publish the public key; stop and investigate any error.

[source,bash,role=execute]
----
export HOME=/tmp/lab-home
mkdir -p "${HOME}"
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000
COSIGN_PASSWORD="" cosign sign --key /home/lab-user/lab-trust/cosign.key \
  --tlog-upload=false \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE}" || { echo "Signing failed"; exit 1; }
# ImagePolicy signedEmail cannot be a SA URI. Publish the public key for 6.1.
oc -n tssc-admission create configmap lab-cosign-pubkey \
  --from-file=cosign.pub=/home/lab-user/lab-trust/cosign.pub \
  --dry-run=client -o yaml | oc apply -f -
# Tilde follows HOME. Put the real home back before the Check (or use /home/lab-user/lab-trust).
export HOME=/home/lab-user
----

=== Verify with the published public key

Export the public key from `tssc-admission/lab-cosign-pubkey`, compare it with `/home/lab-user/lab-trust/cosign.pub`, and verify the saved application digest with that exported key. `--insecure-ignore-tlog` matches the sign, which did not upload a transparency-log entry. Success is exit code 0 on your application digest. The 5.1 keyless signature has to remain verifiable. Stripping the Fulcio signature fails that later use.

.Verify with the public key
[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap lab-gitea -o jsonpath='{.data.student_build_namespace}')"
IMAGE="$(cat /home/lab-user/lightwell-signing-evidence/image.txt)"
CURRENT_IMAGE="$(oc -n "$BUILD_NS" get istag spring-boot-lw-poc:latest -o jsonpath='{.image.dockerImageReference}')"
[[ "$IMAGE" == *@sha256:* && "$IMAGE" == "$CURRENT_IMAGE" ]] || { echo "Refresh 5.1 verification for the current application digest"; exit 1; }
export HOME=/home/lab-user
LAB_TRUST=/home/lab-user/lab-trust
test -f "${LAB_TRUST}/cosign.pub"
oc -n tssc-admission get configmap lab-cosign-pubkey -o jsonpath='{.data.cosign\.pub}' > /tmp/track5-admission.pub
cmp "$LAB_TRUST/cosign.pub" /tmp/track5-admission.pub \
  || { echo "Admission public key differs from the local key"; exit 1; }
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000
cosign verify --key /tmp/track5-admission.pub \
  --insecure-ignore-tlog \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE}" > /tmp/track5-key-verification.json
VERIFY_STATUS=$?
cat /tmp/track5-key-verification.json
test "$VERIFY_STATUS" -eq 0 || { echo "Public-key verification failed"; exit 1; }
cp /tmp/track5-key-verification.json /home/lab-user/lightwell-signing-evidence/
----

== Review

Confirm that the saved digest still matches the application tag, the exported admission public key matches your local `cosign.pub`, and verification with that exported key succeeds. Repeat the keyless verification in 5.1 to confirm that both signatures remain usable on the same digest. Keep the private key under `/home/lab-user/lab-trust`; neither Git nor the admission ConfigMap needs it.

Explain the boundary of this exercise: verification uses the public key and registry-hosted signature without a transparency-log lookup. The registry is still reachable, and no physical network isolation or mirrored-TUF transfer has been demonstrated. The appendix supplies that separate transfer procedure.

== Carry the result into Track 6

Keep the final `image.txt`, both verification outputs, and the policy reports. Track 6 promotes that signed digest and reads `tssc-admission/lab-cosign-pubkey`. If another build moves the tag, stop and refresh signing, policy, and SBOM evidence for the replacement digest before promotion.
